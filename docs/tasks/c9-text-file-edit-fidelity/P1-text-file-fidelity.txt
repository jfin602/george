TEXT-FRAMING CLASSIFICATION

Implement the narrowest reusable internal classifier needed by read and mutation paths.

For recognized UTF-8 text, expose:

- line-ending convention: `none | lf | crlf | mixed`;
- final-newline style: `none | lf | crlf`.

Requirements:
- classify from the complete current file, not only the returned prefix;
- valid UTF-8 is required;
- NUL-containing input is not ordinary text for this contract;
- bare-CR or otherwise ambiguous newline use must degrade conservatively to `mixed` rather than being silently called LF/CRLF;
- do not add a dependency.

READ_FILE

Extend the canonical `read_file` result with optional text-framing metadata.

Preferred shape:

`textFraming?: { lineEnding: 'none' | 'lf' | 'crlf' | 'mixed'; finalNewline: 'none' | 'lf' | 'crlf' }`

Exact property names may follow repository conventions, but keep the representation small and provider-safe.

Requirements:
- compute framing during the same opened-file full scan that already computes SHA-256;
- no second path reopen between SHA and framing evidence;
- no unbounded full-file buffering solely for classification;
- preserve cancellation;
- preserve current path/text/bytes/truncated/SHA semantics;
- truncated provider text still receives full-file framing;
- invalid UTF-8/NUL input omits text-framing metadata instead of inventing it.

Update the provider-visible `read_file` description to mention current SHA and framing evidence.

MUTATION TOOL CONTRACT

Add one optional explicit acknowledgement to BOTH `write_file` and `apply_patch`:

`allowTextFramingChange?: boolean`

Use that name unless a current naming convention makes a close equivalent materially better.

Default/absence means false.

For an existing target:

1. preserve canonical path resolution and Git snapshot behavior;
2. verify the current-content SHA exactly as today;
3. classify the current file if it is recognized UTF-8 text;
4. construct the exact proposed/result content exactly as today;
5. classify proposed/result framing;
6. before publication, reject an unacknowledged framing change with a bounded recoverable `validation` tool error;
7. if explicit acknowledgement is true, permit the exact requested bytes;
8. publication remains verbatim.

The error should identify only bounded framing facts such as:

`Text framing change requires explicit acknowledgement: current lineEnding=lf finalNewline=lf; proposed lineEnding=lf finalNewline=none.`

Do not echo unrestricted file bodies.

WRITE_FILE

- Existing recognized text target: preserve final-newline state and recognized line-ending convention by default.
- Existing `mixed` target: a full replacement requires `allowTextFramingChange: true` because whole-file framing fidelity cannot be established from the coarse category alone.
- New-file creation: unchanged; there is no prior framing to preserve.
- Existing non-text/unrecognized target: preserve prior mutation behavior rather than inventing a text policy.

APPLY_PATCH

- Keep exact oldText/newText semantics.
- Untouched bytes must remain unchanged.
- If resulting recognized framing differs from current framing, reject unless `allowTextFramingChange: true`.
- A localized patch that leaves framing unchanged proceeds normally.
- Do not force opt-in merely because the current file is `mixed` if an exact patch leaves the recognized framing unchanged; untouched mixed bytes remain intact.

PROVIDER GUIDANCE

Update provider-visible mutation descriptions/schema descriptions so the model knows:

- prefer `apply_patch` for localized changes to existing files;
- `write_file` replaces the entire file exactly;
- preserve `read_file.textFraming` unless the task explicitly asks to change it;
- `allowTextFramingChange` is only an explicit acknowledgement for intentional framing changes;
- the flag is not a formatter and does not make George rewrite content.

STRUCTURED INSPECTION EVIDENCE

Extend the allowlisted `read_file` structured inspection projection to carry valid `textFraming` alongside:
- path;
- bounded/redacted text;
- SHA;
- existing bounded metadata.

Do not durably store raw file bodies in TaskState.

RECOVERABLE MODEL LOOP

A framing rejection must behave as a normal tool failure:
- no file mutation is published;
- current SHA remains valid;
- the provider continuation receives the bounded error;
- the model may retry with corrected content, `apply_patch`, or explicit acknowledgement if the task genuinely calls for a framing change.
