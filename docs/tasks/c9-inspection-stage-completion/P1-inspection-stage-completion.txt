APPLICATION-OWNED TOOL-ROUND COMPLETION

Add the narrowest typed agent-loop submission option that lets a caller finish a bounded turn after the first **successful tool round**.

Preferred semantic shape:

`completeAfterSuccessfulToolRound?: boolean`

or an equivalently narrow typed option.

When absent/false, current loop behavior must remain unchanged.

When enabled:

1. request the provider normally;
2. execute the full admitted tool-call round in provider order using the existing ToolRegistry, policy, approval, budget, and lifecycle paths;
3. after that round completes, inspect the normalized tool results;
4. if at least one tool result is successful, finish the turn successfully without constructing/sending a provider continuation;
5. if every tool result failed/denied, do not claim completion; preserve the existing bounded continuation/failure behavior.

Do not terminate mid-round after the first successful individual call.

Do not bypass a stage/tool limit that is already violated by the provider's round.

TURN / TRANSCRIPT TRUTH

Early successful completion after a tool round must preserve the existing provider-round assistant commit contract:

- text emitted by a provider round containing tool calls remains provisional and must not become canonical assistant transcript/final assistant response;
- all provider/tool lifecycle events remain recorded;
- normal turn-completed hooks/events still run;
- completion must not fabricate assistant text;
- CodingWorkflowCompletion must classify the turn as completed when no actual failure/validation failure exists.

Do not require an extra provider final-text round merely to close INSPECT.

STRUCTURED INSPECT

Enable the new completion option only on the structured INSPECT subrun.

Required behavior:

- first INSPECT provider request still has `toolChoice: required`;
- Qwen may select any/all tools from the existing restricted inspection tool set;
- George executes the admitted tool calls for that first round;
- if at least one successful local-read result is observed, the INSPECT turn ends immediately after the round;
- `StructuredTaskApplicationService` extracts the successful tool events exactly as today;
- bounded stage evidence is recorded;
- the task proceeds to the implementation stage without an inspection continuation provider request.

A failed/denied-only first round does not satisfy INSPECT.

The existing four-call INSPECT ceiling remains a fallback failure guard, not the intended completion mechanism.
