MUTATION INTENT != AUTHORITY

Keep the existing model-visible field:

`allowTextFramingChange?: boolean`

Do not rename or remove it in this correction.

For model-originated calls through the canonical application loop, interpret:

`allowTextFramingChange: true`

as a request/acknowledgement of exceptional text-framing-change intent, NOT as executable permission.

The low-level mutation executor may continue honoring the flag for already-authorized trusted direct callers. Do not move approval logic into the filesystem executor.

APPROVAL REQUEST CONTRACT

Extend `ApprovalRequest` with the smallest bounded optional mutation projection.

Preferred shape:

`mutation?: { intent: 'text_framing_change'; warning: string }`

Requirements:
- stable typed intent;
- George-owned bounded warning;
- no write body;
- no patch edit body;
- no raw generic argument JSON;
- no secrets.

Use a concise warning equivalent to:

`Existing text framing will change if this mutation is allowed.`

APPLICATION APPROVAL CONSTRUCTION

After ToolRegistry validation, detect `write_file` / `apply_patch` calls whose validated arguments contain `allowTextFramingChange === true`.

Inside the workspace:

STANDARD MODE
- preserve the existing mutation approval requirement;
- include the bounded `mutation.intent=text_framing_change` projection in that approval request.

WORKSPACE AUTONOMOUS
- ordinary qualified workspace mutations remain auto-runnable exactly as today;
- framing-change intent MUST produce an approval request instead of auto-running;
- only `allow_once` may authorize dispatch.

OUTSIDE WORKSPACE
- preserve reject/ask semantics;
- if an outside mutation approval is generated and the same exceptional intent is present, include the bounded mutation projection;
- framing intent must not weaken outside-workspace authority.

DENIAL

If approval is denied:
- do not dispatch the mutation executor;
- do not emit successful mutation/recovery intent;
- preserve target bytes/SHA;
- emit normal `approval.denied` and `tool.failed code=denied`;
- allow the provider continuation to recover normally.

Do not treat model narration or Task Prompt text as approval.

QUALIFICATION-SPECIFIC GATE A APPROVAL

Do NOT broaden the historical agentic benchmark definition or expected tool set.

Add a repository-owned Phase 9 frozen-edit qualification approval helper in the qualification layer.

Preferred API shape:

`createFrozenEditQualificationApproval({ targetPath, validation })`

or a comparably narrow name.

It must return an `ApprovalPort` that:

- allows `write_file` on exactly the approved target ONLY when no exceptional mutation intent is present;
- allows `apply_patch` on exactly the approved target ONLY when no exceptional mutation intent is present;
- denies unrelated mutation targets;
- denies any `text_framing_change` intent;
- allows only the exact expected validation executable/argv;
- denies every other request.

Do not rely on model-visible file content to decide approval.

If `createBenchmarkApproval` is changed at all:
- it may be hardened to deny exceptional mutation intent;
- it must NOT start allowing `apply_patch`;
- historical benchmark expected tools/cases remain unchanged.
