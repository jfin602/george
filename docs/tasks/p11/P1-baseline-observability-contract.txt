REQUIREMENTS

- R1: Create a presentation-independent Observability Projection v1 module/type surface under application/core. It must not depend on OpenTUI, daemon transport, Tauri, browser UI, or LM Studio-specific wire payloads.
- R2: Version the projection schema explicitly and fail explicitly on unsupported serialized schema versions where serialization/parsing exists.
- R3: Define bounded read-only projections for run/turn/provider-round/request-section/tool-exposure/context/task/validation/correction/budget relationships required by the Phase 11 contract.
- R4: Reuse existing canonical IDs rather than inventing parallel identity: session, turn, run, provider attempt, tool call, task/stack fingerprint, work unit, validation/correction where available.
- R5: Distinguish canonical evidence from derived observability projection in code/types/docs. Projection state cannot grant permission, execute a tool, validate work, advance TaskState, cancel a run, or mutate session truth.
- R6: Define provider-round projection bounds:
  - safe individual text preview <= 8 KiB;
  - complete provider-round projection <= 64 KiB or explicit truncation/metadata-only fallback;
  - tool schemas may degrade to identity/size metadata when bounded projection would overflow.
- R7: Define deterministic redaction/preview disposition so credentials/secrets, raw process environment, provider adapter credentials, unrestricted mutation/process bodies, raw provider wire payloads, hidden reasoning and unrestricted provisional Operation prose cannot enter the projection.
- R8: Define RequestSectionProjection semantics for intentionally provider-visible ordered sections with kind, source/provenance identity when known, byte count, estimated token count, order and preview/redaction disposition.
- R9: Define ToolExposureProjection semantics for name, effect, replay-safety, source and schema size without allowing adapter secrets into the projection.
- R10: Define mutation-selection observability fields needed later to distinguish GEP eligibility/receipt/fallback from the mutation mechanism actually selected.
- R11: Define context/task correlation fields by referencing existing ContextDiagnostics and TaskState/StackState authority rather than copying them into a separately mutable state model.
- R12: Add deterministic unit tests for schema versioning, immutability/read-only behavior, bounds, truncation, redaction, correlation identity and canonical/derived separation.
- R13: Create `docs/tasks/p11/P1-baseline-identity.md` recording the exact inherited Phase 10 owner-accepted baseline, current package/Git identity, known live GEP-selection Not Green result and fields intentionally unavailable before P2.
- R14: Preserve every Phase 10 owner waiver and historical Not Green/Evidence Gap exactly; P1 must not perform GEP selection tuning or another performance optimization.
- R15: Set package version to `0.11.1`; do not create package-lock.json.
