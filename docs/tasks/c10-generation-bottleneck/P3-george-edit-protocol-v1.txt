REQUIREMENTS

- R1: Define a versioned George Edit Protocol v1 parser/contract for Operation-mode text mutation packets.
- R2: GEP/1 is application-owned and provider-independent. LM Studio remains unaware of GEP semantics beyond ordinary streamed text/function transport.
- R3: For complete eligible UTF-8 Operation-mode `read_file` observations, create short bounded run-local receipt IDs mapped ephemerally to canonical path, full current SHA-256, exact complete snapshot, text framing, and current freshness/mutation epoch.
- R4: Do not persist receipt file bodies or treat the receipt map as canonical durable state. Restart/recovery requires fresh read evidence.
- R5: Provider-facing eligible read evidence must expose deterministic compact line addresses so the model can reference replacement ranges without echoing old source text.
- R6: GEP/1 existing-file edits must identify a receipt and one or more non-overlapping line ranges plus replacement content. All ranges are interpreted against the original receipt snapshot.
- R7: GEP/1 must support creation of a new bounded UTF-8 text file without requiring legacy JSON `write_file` framing.
- R8: Support multiple independent edit/create operations in one completed packet when every member is prevalidated and unambiguous.
- R9: Use robust bounded packet framing. If a George-supplied unique delimiter/sentinel is used, collision or malformed framing must fail closed before any side effect.
- R10: Reject before mutation on unknown/stale receipt, truncated/ineligible snapshot, unsupported/mixed framing where exact conversion is not safe, out-of-range lines, overlapping ranges, duplicate ambiguous target, malformed packet, unknown version, NUL/invalid text, or byte/edit/file limit overflow.
- R11: Parse and prevalidate the complete packet only after `provider.response.completed`; no GEP side effect may execute from a partial/incomplete response.
- R12: Expand every accepted existing-file edit into the inherited canonical mutation path using George-derived path, expected SHA, exact old text/range content, replacement text, and framing evidence.
- R13: Expand accepted new-file creation into the inherited canonical write mutation path.
- R14: Preserve ToolRegistry effect classification, execution policy/approval, workspace containment, recovery intent, Git/direct-mutation evidence, mutation epochs, provider-safe mutation receipts, cancellation, and outcome-unknown semantics.
- R15: Human mode remains conversational. Operation mode may produce normal typed tools, GEP/1 packets, or the existing non-executable handoff control.
- R16: Define one explicit fail-closed rule for ambiguous mixtures such as GEP text plus executable tool calls/control in the same completed response.
- R17: Existing `write_file` and `apply_patch` remain supported compatibility/fallback surfaces. Do not delete or weaken them.
- R18: For eligible structured text mutations, adjust Operation-mode guidance/tool exposure so GEP/1 is the normal compact path rather than continuing to force path/SHA/oldText/newText legacy emission.
- R19: Add bounded aggregate metrics for GEP packet bytes, expanded canonical mutation bytes, receipt count, stale-receipt rejection, and mutation transmission ratio. Do not persist raw source bodies solely for metrics.
- R20: Add a deterministic representative existing-file edit fixture and prove `Mutation Transmission Ratio = GEP packet bytes / equivalent expanded canonical mutation bytes <= 0.70`, with byte-identical final output.
- R21: Add permanent parser/security regressions covering single/multiple edits, multiple files, create, delete/empty replacement where supported, delimiter collision, malformed/unknown version, stale/unknown receipt, overlap, out-of-range, oversized/NUL/invalid text, response incompleteness, mixed output, framing, SHA drift and cancellation.
- R22: Preserve package `0.10.12`; do not create package-lock.json.

INVARIANTS

- I1: Compact protocol changes model transmission, not executable authority.
- I2: Current-content SHA is rechecked at execution.
- I3: The model never supplies authoritative path/SHA/old text for an eligible receipt edit.
- I4: No mutation executes before the whole GEP response is completed and validated.
- I5: A stale receipt fails rather than silently rebasing.
- I6: Unsupported targets fall back to inherited safe mutation behavior rather than unsafe approximation.
- I7: Do not change read concurrency, context profiles, helper behavior, or browser tooling.
