REQUIREMENTS

- R1: Introduce canonical TaskState bound to one canonical session/workspace and one parsed task definition/fingerprint.
- R2: Track overall task status, current work unit, requirement state, work-unit dependency/status, inspection evidence, validation attempt history, correction count/history, blockers, terminal outcome, and effective permission expectation snapshot.
- R3: Distinguish requirement addressed state from validation-backed verified state; model text alone cannot set requirement or validation Green.
- R4: Implement deterministic transition functions that reject illegal dependency/state transitions rather than repairing them silently.
- R5: Preserve all failed validation attempts; a later pass updates current state but never erases earlier failure evidence.
- R6: Use an explicit bounded correction-cycle field/config with default 2 and validate its range.
- R7: Extend Session/LocalSessionStore with bounded/redacted TaskState persistence and a deliberate schema upgrade while retaining the ability to open existing schema-v1 sessions with no task state.
- R8: Unsupported future/malformed durable task/session state must fail visibly and must not be partially trusted.
- R9: Provide presentation-safe bounded TaskState projections without raw prompt bodies, file bodies, process output, secrets, or provider payloads.
- R10: Set package version to 0.9.2 and add permanent state/persistence regression coverage.

INVARIANTS

- I1: Canonical TaskState is George state, not model reasoning and not automatically provider context.
- I2: Task state cannot grant tools, permissions, network, filesystem scope, or validation success.
- I3: Existing non-task sessions remain valid and reopenable.
- I4: Phase 5 interruption/recovery evidence remains authoritative for ambiguous side effects.
- I5: No package-lock.json is created.
