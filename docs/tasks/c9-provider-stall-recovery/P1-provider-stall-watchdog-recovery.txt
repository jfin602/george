STALL POLICY

Add one validated application-owned provider stall policy.

Initial intended defaults:
- suspected-stall visibility at approximately 60000 ms without provider/wire activity;
- first-evidence recovery at approximately 90000 ms;
- post-activity inactivity recovery at approximately 60000 ms;
- absolute provider request timeout remains exactly 120000 ms;
- at most 1 stall-specific identical fresh retry per canonical provider round;
- at most 1 canonical rebase attempt after the repeated eligible stall.

If current deterministic/runtime evidence requires a nearby safer threshold, document the reason in the P1 final response and tests. Do not simply lower the global provider timeout.

PROVIDER ACTIVITY

Add the smallest provider-independent activity seam needed for watchdog accuracy.

The LM Studio adapter may report bounded wire activity such as valid SSE frame receipt even when the function-call assembler has not yet emitted a semantic tool call.

Requirements:
- no raw SSE payload persistence;
- no unbounded activity events;
- adapter does not decide retry/rebase;
- provider implementations that do not supply extra activity remain valid because semantic ProviderEvents also refresh liveness.

WATCHDOG

Implement application-owned per-attempt watchdog state for:
- awaiting first evidence;
- response active;
- response completed.

Use a watchdog-owned AbortController combined with the caller signal.

Classify:
- caller abort -> `cancelled`;
- watchdog abort -> provider stall;
- provider absolute timeout -> provider timeout;
- normal completion -> no stall.

Clean up every timer/controller.

Do not allow a stale timer to cancel a later attempt.

SAFE FRESH RETRY

Preserve and extend the current P2 replay-safe incomplete-response logic.

A stalled branch may receive one identical fresh retry only when:
- response incomplete;
- no tool proposed by that failed branch executed;
- no canonical assistant response committed;
- no ambiguous external/local/remote side effect;
- policy/cancellation/budgets allow it.

Discard provisional text/tool proposals and incomplete response ID.

They are diagnostic evidence only.

CANONICAL REBASE

If that eligible fresh retry also stalls, do not issue another identical retry.

For structured implementation/correction stages, rebuild one new provider request from George-owned canonical state/evidence.

The rebased request must not reuse the failed provider-native `previous_response_id`.

Preserve, bounded:
- current user/task objective;
- active work unit/completion condition;
- mission card;
- applicable requirements/invariants/stops;
- effective permission constraints;
- valid current inspection/tool evidence;
- current SHA/text-framing evidence when valid;
- completed prior-round tool-result evidence needed to continue;
- unresolved provider/tool/validation/recovery failures;
- pending George-owned validation/completion condition.

Do not invent state or mark completion by model inference.

If safe reconstruction is unavailable, terminate provider failure rather than guessing.

CONTEXT PRESSURE

A stall is not proof of context overload.

Use current request estimate plus effective profile pressure.

After the repeated eligible stall:

LOW PRESSURE
- do not semantic-compact merely because of the stall;
- perform the one canonical rebase directly.

HIGH PRESSURE
- if older completed history is safely compactable, allow one bounded stall-pressure compaction/reduction before rebase;
- otherwise preserve critical current state and rebase safely or terminate.

Continuation/tool-result growth must participate in the pressure decision.

COMPACTOR RECURSION GUARD

The default semantic compactor uses the same provider.

A compaction initiated by stall recovery:
- may run once;
- has a strict independent timeout/budget;
- cannot recursively enter the normal provider stall retry/rebase ladder;
- records failure;
- falls back only when a non-compacted rebase remains safe.

Do not create a hidden retry loop inside compaction.

TERMINAL TRUTH

If original attempt, fresh retry, and canonical rebase all fail for provider liveness:

- terminate with GeorgeError code `provider`;
- retain bounded stall/recovery metadata;
- do not report `budget_exhausted` unless a real RunBudget/stage budget is actually terminal;
- do not execute provisional tool proposals;
- do not commit provisional assistant text.

DUPLICATE / NO-PROGRESS

Do not weaken the existing guard.

Discarded incomplete branch proposals are not executed tool evidence.

But actual completed rounds and actual/rejected duplicate local reads continue to count normally.

TUI / OBSERVABILITY

Surface bounded derived statuses for:
- suspected stall;
- retrying provider;
- rebuilding provider request;
- stall-pressure compaction when used;
- terminal provider stall.

No raw prompts/provider payloads/file/tool bodies.
