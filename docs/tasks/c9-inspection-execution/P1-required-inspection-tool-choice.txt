PROVIDER-NEUTRAL TOOL CHOICE

Extend the canonical provider request contract with one narrow optional tool-choice mode.

Preferred semantic values:
- `auto`;
- `required`;
- `none`.

The exact type name may follow current conventions, but it must remain provider-neutral.

Requirements:
- absent preserves current behavior;
- `required` requires at least one exposed tool;
- the field can only control whether the model must choose from already-exposed tools; it cannot add capabilities;
- provider adapters must not silently ignore an explicitly required mode.

LM STUDIO MAPPING

Map the provider-neutral mode to the OpenAI-compatible JSON `tool_choice` field for LM Studio.

Permanent adapter tests must inspect the actual POST body and prove:
- required -> `tool_choice: "required"`;
- auto -> `tool_choice: "auto"`;
- none -> `tool_choice: "none"`;
- absent -> field omitted;
- function-tool schema is otherwise unchanged;
- stateful continuation still serializes correctly.

Do not put Qwen-specific conditional logic in core/application code.

FIRST-ROUND APPLICATION SEMANTICS

Add the smallest AgentLoop submission seam needed to require a tool call on **only the first provider round** of one application-owned stage.

Required behavior:
- initial provider request can use `toolChoice: required`;
- after the first tool call/result produces a continuation, later provider requests revert to ordinary automatic/default tool choice;
- a required first round with zero selected tools fails deterministically before provider execution;
- retries of the same initial provider request retain the same required semantics until that round succeeds/fails;
- continuation retries do not become required merely because the first round was required.

STRUCTURED INSPECT

Apply first-round required tool choice only to structured INSPECT.

Keep:
- tool surface exactly `read_file`, `list_directory`, `search_text`, `git_status`, `git_diff`;
- current INSPECT stage limits;
- observed tool completion as the only evidence that satisfies inspection.

Do not:
- force a specific inspection tool;
- synthesize inspection evidence;
- auto-read guessed paths;
- use required tool choice for ordinary implementation/correction stages by default.

If the provider/backend rejects required tool choice, fail visibly with provider evidence rather than silently accepting text-only inspection.
