PROBLEM

The current watchdog treats response acceptance as active output.

The local Responses path can create/accept a response and then spend a long interval in prompt prefill with no semantic output event.

That causes legitimate prefill to hit the shorter active-inactivity threshold.

REQUIRED SEMANTICS

Distinguish:
- response acceptance/identity;
- useful output progress;
- response completion.

`provider.response.started` / wire `response.created` must NOT by itself activate the short output-inactivity timer.

First-useful-output allowance continues through accepted prefill.

Useful output progress includes:
- text generation;
- function-call/control-call generation progress;
- equivalent provider output-progress signals that are payload-free and bounded.

Once useful output begins, the active-output inactivity timer applies.

Do not scrape LM Studio server logs.

PROVIDER ACTIVITY SEAM

Refine `ProviderStreamOptions.onActivity` or replace it with the smallest typed provider-independent equivalent.

The LM Studio adapter may classify valid SSE activity as:
- accepted;
- output progress.

No raw SSE payload crosses the seam.

Application code owns watchdog/retry/rebase decisions.

PRESERVE

Unless actual current code differs, preserve:
- suspected stall: 60000 ms;
- first useful output: 90000 ms;
- active output inactivity: 60000 ms;
- absolute provider timeout: 120000 ms;
- max stall fresh retry: 1;
- max canonical rebase: 1;
- 30000 ms one-shot stall compaction;
- replay-safe provisional-branch discard;
- caller cancellation authority.

Do not inflate timeouts to pass.
