READ_FILE HASH CONTRACT

Extend the canonical `read_file` result with:

`sha256: string`

Requirements:
- lowercase 64-character SHA-256;
- hash represents the **full current file bytes**, not only the returned/truncated text prefix;
- compute from the same opened file instance used for the read so the returned text/hash pair is not assembled from two independently reopened path versions;
- do not load arbitrarily large files wholly into memory solely to hash them;
- preserve canonical workspace/symlink containment;
- preserve cancellation/bounds where applicable;
- preserve existing `path`, `text`, `bytes`, and `truncated` behavior unless a current contract requires a deliberate documented clarification.

MUTATION TOOL GUIDANCE

Keep mutation safety unchanged.

Provider-visible metadata must clearly communicate:
- `read_file` returns the current SHA-256 mutation precondition;
- when `write_file` overwrites an existing file, `expectedSha256` must be the latest observed `read_file.sha256`;
- `apply_patch.expectedSha256` must likewise use the latest observed current-file hash;
- creating a new file remains distinct from overwriting an existing file.

Do not silently auto-fill `expectedSha256` behind the model's back.
Do not weaken current-content precondition checking.

STRUCTURED EVIDENCE

Update the bounded structured inspection projection so a successful `read_file` evidence item includes:
- path;
- bounded/redacted text;
- full-file `sha256`;
- existing bounded metadata.

The provider-facing implementation slice must therefore contain the exact hash needed for the next safe mutation.

Do not persist raw file bodies into canonical TaskState.

PERMANENT REGRESSION COVERAGE

1. `read_file` returns the correct SHA-256 for a normal file.

5. A hash obtained from actual `read_file` output can be passed directly to `apply_patch`.
