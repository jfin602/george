REQUIREMENTS

- R1: Replace destructive GEP read projection with an additive bounded provider result for eligible Operation-mode `read_file` observations.
- R2: Preserve the inherited provider-visible fields required by compatibility consumers: `name`, `path`, `text`, `bytes`, `truncated=false`, `sha256`, and `textFraming`.
- R3: Add GEP metadata without creating a second canonical snapshot. Prefer a nested or otherwise clearly namespaced GEP projection containing the short receipt ID and deterministic numbered-line view.
- R4: Keep the exact receipt snapshot/SHA/framing/epoch only in the bounded run-local receipt registry. Do not add raw source bodies to durable events/diagnostics merely for GEP.
- R5: Add one centralized maximum serialized provider-visible dual-projection size of 16 KiB.
- R6: If the complete dual projection would exceed 16 KiB, return the inherited legacy provider result unchanged and do not expose a provider-usable GEP receipt for that result.
- R7: Truncated, binary, mixed/unsupported framing, invalid UTF-8, or otherwise GEP-ineligible reads continue to return unchanged inherited provider evidence.
- R8: A hidden/internal receipt must never be usable by the model when its GEP provider metadata was withheld due to the projection bound.
- R9: Legacy `write_file` / `apply_patch` remain advertised and executable compatibility/fallback tools.
- R10: Frozen Phase 8 structured replay must again observe SHA/framing and complete its legacy write/framing rejection/reread/patch path unchanged.
- R11: Frozen framing-authority recovery must again observe reread SHA and complete its safe legacy patch path unchanged.
- R12: Update P3-era regressions that asserted SHA absence. Replace them with additive/bounded coexistence assertions rather than weakening the frozen compatibility tests.
- R13: Preserve GEP current-SHA recheck, stale receipt rejection, original-snapshot range semantics, text framing, permission/recovery intent, response-completion-before-mutation and legacy mutation compatibility.
- R14: Add deterministic byte accounting for one representative existing-file edit:
  - inherited legacy read provider bytes;
  - bounded dual GEP read provider bytes;
  - equivalent legacy mutation argument bytes;
  - GEP packet bytes.
- R15: Retain `Mutation Transmission Ratio = GEP packet bytes / legacy mutation argument bytes <= 0.70`.
- R16: Add `Net Edit Transport Ratio = (dual GEP read bytes + GEP packet bytes) / (legacy read bytes + legacy mutation argument bytes)` and require it to be < 1.0.
- R17: Resulting files in the representative fixture must remain byte-identical between GEP expansion and canonical expected output.
- R18: Ensure continuation/context accounting measures the actual projected provider result and does not count hidden receipt state.
- R19: Preserve package `0.10.12`; do not create package-lock.json.
